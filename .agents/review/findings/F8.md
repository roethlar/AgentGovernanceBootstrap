original dirtiness is checked once, later transforms see earlier outputs,
and the archive date is an explicit input. Compatibility wrappers preserve
the existing applying entry points until F8b switches the operation flow.

## F8b — complete operation protocol

Schema 3 includes composed repair actions, original/output hashes, readable
diffs, a frozen date, prepared-path exclusions and explicit target-pin mode.
Apply recomputes and compares before writing; final repair preflight checks
custody, safe destinations and unchanged input bytes. Old schema records
require regeneration and fresh approval. Draft reservations suppress only
repo-owned seeds and mechanical repairs, never shipped custody checks.

The legacy mode pins the sole parent and complete post-carve-out tree.
Commit metadata may differ; provenance for that commit is represented by
its pinned tree so the operation digest remains stable. All applying modes
use the same computed outputs, and the old apply-time repair helpers are gone.

Verification: 251 tests passed, one filesystem-dependent skip (252 total). Coverage includes
all three modes, all repairs, absent/existing archives, overlapping transforms,
dirty inputs, unrelated staging, ignored/unsafe destinations, historical date
replay, schema refusal, normalized/reserved draft and banner paths, seeded
policy ownership, retained foreign custody, parent/tree/toolkit/input drift,
and different commit metadata with the same approved content.

The original omission reproduces against `e7d41f2`. Nine further isolated
mutations produce assertion failures for composition, ignore protection,
date pinning, draft exclusion, seed ownership, final input preflight,
parent/tree pins and metadata normalization. Restoring the implementation
passes the full suite; whitespace check passes. This establishes validation
before writes, not a whole-filesystem transaction guarantee.

## F8c — bootstrap approval and rehearsal

Bootstrap, verification and the approval summary now account for every
recorded group. Standard drafts/banners reserve their destinations before
planning. Legacy rehearsal freezes the settled policy and prepared inputs,
generates the second operation after commit 1, and applies that same record
in rehearsal and reality. The final repaired files are inspected without
re-copying the original drafts. Pre-commit-1 drift requires replanning.

The read-only pre-commit-1 comparisons are procedure steps, not a new runtime
CLI guard. The runtime independently enforces parent/tree/operation pins
before commit 2. A failed comparison never authorizes bypassing that check.

Manual protocol rehearsal on 2026-11-17 used disposable fixture repositories
and the current runtime. The standard route planned reservations, copied
drafts/banners, applied once, and made exactly one scoped commit with draft
hashes intact. The legacy route made exactly two commits; rehearsal and
real-target final trees and repair hashes agreed, including an added archive.
Final readout retained the repaired decision file and archive, without recopy.
Read-only comparisons detected changed draft, non-default push policy,
scope/message, base, toolkit and manifest before real carve-out mutation;
the target snapshot stayed unchanged in every negative case.

All 251 tests passed, one filesystem-dependent skip (252 total); whitespace check passes.

final repaired files. F8 implementation and integration are complete;
